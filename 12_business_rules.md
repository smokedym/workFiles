# Бизнес-правила и машины состояний

## Обзор

Документ описывает все бизнес-правила приложения, машины состояний, диаграммы процессов и ограничения предметной области.

---

## 1. Полный бизнес-процесс инспекции

```
┌─────────────────────────────────────────────────────────────┐
│                    ЦИКЛ ИНСПЕКЦИИ ВОЛС                      │
└─────────────────────────────────────────────────────────────┘

[1] ВХОД В СИСТЕМУ
    ├── Ввод логина/пароля
    ├── Смена пароля (если требуется)
    └── Принятие соглашения (если требуется)
           │
           ▼
[2] СИНХРОНИЗАЦИЯ (по желанию)
    ├── Выгрузить предыдущие инспекции (Push)
    └── Загрузить актуальные задания (Sync)
           │
           ▼
[3] ВЫБОР ЗАДАНИЯ
    └── Из списка доступных заданий
           │
           ▼
[4] ВЫБОР ЛИНИИ ЭЛЕКТРОПЕРЕДАЧИ
    └── Из линий, включённых в задание
           │
           ▼
[5] ПРОСМОТР КАРТЫ
    └── Опоры линии отображаются как маркеры
           │
           ▼
[6] ВЫБОР ОПОРЫ ДЛЯ ИНСПЕКЦИИ
    └── Тап по маркеру на карте
           │
           ▼
[7] ИНСПЕКЦИЯ ОПОРЫ
    ├── Фотофиксация (обязательно, с GPS)
    └── Добавление объектов ВОЛС (опционально)
           │
           ▼
[8] ДОБАВЛЕНИЕ ОБЪЕКТОВ ВОЛС (для каждого оператора)
    ├── Выбор оператора
    ├── Добавление типов устройств с количеством
    ├── Фотографии объектов ВОЛС
    ├── Дата монтажа
    ├── Примечания
    └── Флаг маркировки
           │
           ▼
[9] ЗАВЕРШЕНИЕ ОСМОТРА ОПОРЫ
    └── Пометить для выгрузки (pushStatus = WAIT_PUSH)
           │
           ▼
[10] СИНХРОНИЗАЦИЯ (обязательна для отправки)
    ├── Push: Загрузить инспекцию на сервер
    └── pushStatus → WAIT_VERIFY
           │
           ▼
[11] ПРОВЕРКА СЕРВЕРОМ
    ├── ПРИНЯТО (pushStatus = ACCEPTED) → Готово ✓
    └── ОТКЛОНЕНО (pushStatus = DENIED)
               │
               ▼
    [12] ИСПРАВЛЕНИЕ И ПОВТОРНАЯ ОТПРАВКА
         └── Повторить с шага [7]
```

## 2. Машина состояний инспекции опоры

### WorkStatus (статус выполнения)

```
                  ┌─────────────┐
        ┌────────►│ NOT_STARTED │◄───────────┐
        │         └──────┬──────┘             │
  del photo,             │                  del photo
  del all vols    add photo│add vols        del vols
        │                 │                   │
        │    ┌────────────┼────────────┐      │
        │    ▼            ▼            ▼      │
        │  ┌─────┐  ┌─────────┐  ┌──────────┐│
        │  │W/O  │  │  W/O    │  │  WITH    ││
        │  │CAPT │  │  VOLS   │  │  VOLS    ││
        │  └──┬──┘  └────┬────┘  └──────────┘│
        │     │add        │add               │
        │     │photo      │vols              │
        │     │           │                  │
        │     └───────────┘──────────────────┘
        │              del photo/vols
```

| Состояние | Фото | ВОЛС | Цвет маркера |
|----------|------|------|-------------|
| `NOT_STARTED` | ✗ | ✗ | Серый |
| `WITHOUT_CAPTURE` | ✗ | ✓ | Оранжевый |
| `WITHOUT_VOLS` | ✓ | ✗ | Жёлтый |
| `WITH_VOLS` | ✓ | ✓ | Зелёный/Синий/Красный (по pushStatus) |

### PushStatus (статус выгрузки)

```
NOT_PUSHED
    │
    │ (FinishPillarView)
    ▼
WAIT_PUSH ──────────────────────────────┐
    │                                   │ (ошибка частичной выгрузки)
    │ (PushExecutor успешно)             ▼
    ▼                             PUSH_NOT_COMPLETE
WAIT_VERIFY                             │
    │                                   │ (повторная попытка)
    ├─── isAccepted=true ──────────────►│
    │           │                       └─► WAIT_VERIFY
    │           ▼
    │        ACCEPTED (только чтение, навсегда)
    │
    └─── isAccepted=false
                │
                ▼
             DENIED (редактируется, можно переотправить)
                │
                │ (FinishPillarView)
                ▼
             WAIT_PUSH (цикл повторяется)
```

### Правила редактируемости

```
isEditable = pushStatus IN (NOT_PUSHED, WAIT_PUSH, DENIED)

Редактируемые состояния:      NOT_PUSHED, WAIT_PUSH, DENIED
Только для чтения:            PUSH_NOT_COMPLETE, WAIT_VERIFY, ACCEPTED
```

## 3. Бизнес-правила паролей

```
Пароль валиден если ВСЕ условия выполнены:
  ✓ длина >= 12 символов
  ✓ есть хотя бы 1 символ верхнего регистра [A-Z]
  ✓ есть хотя бы 1 символ нижнего регистра [a-z]
  ✓ есть хотя бы 1 цифра [0-9]
  ✓ есть хотя бы 1 спецсимвол из: !@#$%^&*()_+-=[]{}|;:,.<>?/~
```

---

## 4. Правила фотофиксации

1. **Обязательность**: нельзя завершить осмотр (`FinishPillarView`) без фото
2. **Одно фото на инспекцию**: у `PillarInspectionEntity` ровно одно `photoId`
3. **GPS при съёмке**: каждое фото автоматически записывает координаты
4. **Фото ВОЛС**: необязательные, количество не ограничено
5. **Удаление фото**: если фото уже выгружено (есть `serverId`), добавляется в `DeletePushEntity`

## 5. Правила синхронизации

```
Порядок операций при нажатии "Синхронизировать":
  1. PUSH (выгрузка) → SYNC (загрузка)
  Нельзя выполнить только SYNC без PUSH.

Причина: избежать перезаписи локальных изменений серверными данными.

Условия для Push объекта:
  - pushStatus == WAIT_PUSH
  - Все зависимости загружены (фото → инспекция → vols → items → фото vols)

Условия для Sync:
  - Push завершён без ошибок
  - Есть сетевое соединение
```

## 6. Правила управления токенами

```
При старте приложения:
  1. Проверить токен в KVault
  2. Если (currentTime >= tokenReceiveTime + expiresIn):
       → Попытаться обновить через refreshToken()
       → Сетевая ошибка? → продолжить (офлайн-режим)
       → Другая ошибка? → принудительный вход
  3. Refresh token истёк? → принудительный вход

При 401 от сервера (Ktor Auth plugin):
  → Автоматически вызвать refreshToken()
  → Повторить запрос с новым токеном
  → Если refresh не удался → выход из системы
```

## 7. Правила работы с ВОЛС

```
Одна опора может иметь:
  - Любое количество групп ВОЛС (по операторам)
  - Ноль или более групп ВОЛС

Одна группа ВОЛС:
  - Принадлежит ровно одному оператору (или без оператора)
  - Содержит ноль или более позиций устройств
  - Содержит ноль или более фотографий

Один тип устройства в группе:
  - Встречается не более одного раза (дедупликация по typeId)
  - Количество >= 1 (при 0 → удаляется из списка)

Удаление группы ВОЛС:
  - Каскадно удаляет все позиции (VolsItem)
  - Каскадно удаляет все фото (VolsCapture)
  - Если есть serverIds → добавить в DeletePushEntity
```

## 8. Правила DeletePushEntity

```
Объект добавляется в очередь удалений если:
  - Удалён локально
  - У него есть serverId (т.е. он уже был выгружен на сервер)

Объект НЕ добавляется если:
  - serverId == null (никогда не выгружался → просто удаляем из БД)

При Push:
  - HTTP 500 на удаление → считать успехом (сервер уже не видит объект)
  - HTTP 4xx → оставить в очереди
  - Успех → удалить из DeletePushEntity
```

## 9. Правила карты

```
Отображение маркеров:
  - Маркер показывается для каждого PillarListItem
  - Цвет определяется по комбинации workStatus + pushStatus
  - Кластеризация: при zoom < 12 близкие маркеры объединяются

Выбор опоры:
  - Тап по маркеру → currentPillarId = taskPillarId
  - Камера анимированно перемещается к опоре
  - Открывается панель инспекции

Вписывание в экран:
  - При выборе линии → автоматически камера вмещает все опоры
  - Padding: 50dp от края экрана
```

## 10. Ограничения offline-режима

| Операция | Offline | Online |
|----------|---------|--------|
| Просмотр заданий | ✓ (из кэша) | ✓ |
| Инспекция опоры | ✓ | ✓ |
| Добавление ВОЛС | ✓ | ✓ |
| Фотофиксация | ✓ | ✓ |
| Синхронизация | ✗ | ✓ |
| Выгрузка (Push) | ✗ | ✓ |
| Получение результатов проверки | ✗ | ✓ (через Sync) |

## 11. Приоритеты данных при конфликтах

```
При синхронизации (загрузке с сервера):
  Если объект уже есть локально:
    → UPSERT: серверные данные перезаписывают локальные

  Исключение: инспекции с pushStatus IN (NOT_PUSHED, WAIT_PUSH):
    → Локальные данные имеют приоритет
    → WorkStatus пересчитывается на основе локального контента
```

## 12. Порядок стартовой проверки (StartCheckResult)

```
Приоритет проверок при запуске (от высшего к низшему):

1. OFFLINE флейвор              → MAIN (пропустить всё)
2. needReLogin                  → LOGIN (isReLogin=false)
3. Не авторизован               → LOGIN
4. passwordChangeInProgress     → RE_LOGIN
5. agreementInProgress          → AGREEMENT
6. accessToken истёк
   └── refreshToken успешен     → продолжить
   └── сетевая ошибка           → MAIN (офлайн)
   └── другая ошибка            → LOGIN
7. Есть непринятые соглашения   → AGREEMENT
8. mustChangePassword           → CHANGE_PASSWORD
9. Всё в порядке                → MAIN
```
